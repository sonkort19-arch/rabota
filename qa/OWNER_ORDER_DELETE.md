# Удаление заказа — только владелец

## Поведение интерфейса

Владелец открывает «Заказы» → нужный заказ → «Изменить» → «Удалить заказ». В форме нового заказа кнопка скрыта. Для менеджера и мастера кнопка всегда скрыта. При существующей оплате она недоступна.

Для удаления нужны два подтверждения: окно с именем клиента, датой и временем и ручной ввод точного слова **УДАЛИТЬ**. Нажатие кнопки НЕ удаляет ничего до подтверждения.

Удаление выполняется только через `POST /rest/v1/rpc/rabota_delete_order`. В браузере нет разрешённого `DELETE rabota_orders`.

## Защита базы

Функция проверяет `auth.uid()`, активную роль **owner**, блокирует строку `FOR UPDATE`, затем повторно запрещает удаление при:
- `paid=true` или любом заполненном поле оплаты;
- финансовых операциях `rabota_finance_operations`;
- кассовых распределениях `rabota_cash_collections`;
- связанных черновиках/подтверждениях `rabota_ai_order_drafts`.

Если заказ не найден, функция возвращает ошибку. Сопутствующие уведомления об удалённом заказе удаляются по существующему `ON DELETE CASCADE`; историю финансов не меняет. Если лид был привязан к заказу, сам лид сохраняется.

Нет нового DELETE RLS policy. `EXECUTE` разрешён `authenticated`, запрещён `anon` и `PUBLIC`, а владельца проверяет сервер.

## Выпуск / проверка

1. Проверить схему и полномочия на production.
2. Применить `sql/006-owner-safe-delete-order.sql` **без удаления заказов**.
3. Убедиться, что у `anon` нет EXECUTE, у authenticated есть только доступ к функции с внутренней проверкой.
4. Выпустить UI в `main` и убедиться, что Vercel собрал соответствующий коммит.
5. Протестировать владельца, менеджера, мастера и случай с оплаченной заявкой в отдельной тестовой базе. Реальные заказы не удалять для QA.

Откат: `sql/007-revoke-owner-delete-order.sql` убирает возможность дальнейшего удаления, но **не восстанавливает уже удалённые записи**. Для восстановления нужен отдельный резервный архив. Текущий Supabase план Free: автоматические ежедневные копии не подтверждены.

PR №25 в этой задаче не объединяется.
