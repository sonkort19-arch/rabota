# Этап 1/10 — защита оплаченных заказов (предпросмотр)

## Проверенные исходные данные на 13.11.2026
- 41 заказ всего, 29 отмечены оплаченными.
- 14 оплаченных заказов не имеют записи в rabota_cash_collections.
- 20 оплаченных заказов не имеют payment_method/payment_amount/paid_at, включая исторические записи.
- Существующий private.rabota_cash_order_guard защищает только заказы с распределением.

## Что изменяет sql/008-protect-paid-orders.sql
- Новый BEFORE UPDATE-триггер на public.rabota_orders без изменения существующего cash_guard.
- Уже оплаченные заказы нельзя изменять обычным PATCH: сумма, статус, дата, время, исполнитель, клиент и реквизиты.
- Первичная оплата через rabota_record_order_payment не затрагивается (OLD.paid=false).
- Учитывается исторический сценарий: rabota_cash_distribute может заполнить пустые реквизиты уже оплаченного заказа только при вызове назначенным мастером, с неизменной суммой и способом «наличные».
- Нет изменений в чужих таблицах, нет миграции/изменения реальных заказов.

## Проверки
`node --test tests/paid-order-guard.test.cjs` — 5 статических проверок SQL-миграции. Это НЕ заменяет проверки реальной PostgreSQL-базы.

Перед разрешением публикации на отдельной тестовой БД с копией схемы проверить:
1. Редактирование оплаченного заказа => SQLSTATE 23514.
2. Создание и редактирование неоплаченного заказа => работает.
3. rabota_record_order_payment => корректно оплачивает только один раз.
4. rabota_cash_distribute по ранее оплаченному legacy-заказу без реквизитов => возможно один раз, с верными долями.
5. Другие роли не могут менять платёжные реквизиты оплаченных заказов.
6. iPhone/PWA и карточка Рауля не получают регрессий.

## Важно
Этот узкий этап закрывает редактирование **уже оплаченных** заказов. Он не заменяет аудит прямой установки paid=true через INSERT/PATCH у owner/manager, которая пока возможна по существующим RLS-политикам. До публикации полной финансовой защиты нужен отдельный аудит и тесты этого сценария.

### Откат нового защитного слоя
```sql
BEGIN;
SET LOCAL lock_timeout = '5s';
DROP TRIGGER IF EXISTS rabota_paid_order_guard_trigger ON public.rabota_orders;
DROP FUNCTION IF EXISTS private.rabota_paid_order_guard();
COMMIT;
```

Без отдельной команды «на основную» ничего не применять к production.
