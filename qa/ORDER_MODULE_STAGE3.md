# Этап 3/10 — вынос логики заказов из index.html

## Изменено
- Создан `order-model.js` (110 строк): кодирование и декодирование заказов
  (`readOrder`, `serializeOrder`), проверка финансовой истории,
  `persistOrder`, проверка уникального времени и близких записей (менее 200 минут).
- `index.html` вместо встроенной реализации вызывает эти функции через адаптеры
  с прежними именами. HTML-структура, карточки и формы не меняются.
- Код получает зависимости явно: `dbRequest`, `reloadOrders`, `getOrders`,
  роли/пользователь, финансовые коллекции.
- Правила доступа, оплаты, RPC и Supabase сохранены без изменений.

## Метрика рефакторинга
Ветка этапа 2: `index.html` — 2 483 строки.
Ветка этапа 3: `index.html` — 2 429 строк (на 54 строки меньше).
Новый модуль: `order-model.js` — 110 строк.
Уменьшение index.html не доказывает ускорения приложения: это изоляция кода.

## Проверки
- Сравнение старой реализации из этапа 2 и перенесённой реализации:
  21 из 21 проверок совпали на синтетических данных (преобразования, сохранение,
  занятые слоты, близкие записи, связанные финансовые операции).
- `tests/order-model.test.cjs`: 11 проверок в среде JavaScript,
  покрывают POST/PATCH, отсутствие лишней записи при ошибке, оплату,
  типы данных, конфликты времени и правильное подключение скрипта.
- Проверен синтаксис основного JavaScript внутри `index.html`.
